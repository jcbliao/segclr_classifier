## Files and fields

- `targets.duckdb`: database containing `cohort`, `synapses`, `connections`,
  `targets`, `cached_volumes`, `skeleton_status`, and the joined `inventory`.
  The skeleton job writes this database; use the exported files while it runs.
- `targets.csv` / `inventory.parquet`: one row per target, synapse count,
  number of distinct presynaptic cohort cells, volume in nm³ and µm³, L2 chunk
  count, volume status, and known available CAVE skeleton versions.
- `root_ids.txt`: all target IDs, one per line. Preserve IDs as integers or
  strings; floating-point conversions (including spreadsheet autoformatting)
  can lose digits.
- `connections.parquet`: directed presynaptic-to-postsynaptic pairs and counts.
- `cohort.parquet`: exact source cohort, labels, confidence, and splits.
- `skeleton_status.parquet`: individual version checks and UTC timestamps.
- `additional_synapses.parquet` / `additional_queries.json`: count-validated
  CAVE queries for the 13 cohort cells absent from the original outgoing cache.
- `volume_cache/parts/`: resumable new volume measurements.
- `missing_volume_roots.parquet`: frozen work list; do not overwrite while jobs run.

Volumes sum CAVE L2-cache `size_nm3` across the root's level-2 leaves, divided
by 1e9 for µm³. These measure the segmented root, not the synaptic cleft or an
embedding crop. `complete` means every L2 chunk had a cached size;
`lower_bound` means some sizes are missing; `error` and `not_queried` have null
volumes. Existing measurements were reused from `data/partner_volume_cache`;
the new pass queries missing or previously failed roots.

`cave_skeleton_available=true` means at least one checked version exists;
`false` means all requested versions were checked and none exists; null means
availability is still unknown. Version availability is current at the recorded
check time, whereas the root IDs and synaptic connectivity are from v1718.
Skeleton checks only inspect cache existence; they do not generate skeletons.
No embeddings have been generated by this inventory task.

## Reproduce / resume

Use `segclr_db/.venv/bin/python scripts/build_postsynaptic_target_inventory.py`
with `--stage prepare`, `--stage skeletons`, or `--stage export`. The default
`all` prepares, checks skeletons, and exports. Avoid simultaneous writers to
the DuckDB file. To resume volume shards, submit:

```bash
sbatch --array=0-31%4 scripts/sbatch/build_postsynaptic_target_inventory.sh volumes
```

Successful rows in finished parts are skipped. The wrapper enables
`--retry-errors` to re-query failed rows. Persistent errors remain explicit;
rerunning does not silently replace them with zeros.
After workers finish, run `--stage export` to incorporate completed volume parts.

Example against an exported snapshot:

```sql
SELECT root_id, volume_um3, n_synapses, available_skeleton_versions
FROM read_parquet('inventory.parquet')
WHERE volume_status = 'complete' AND cave_skeleton_available
ORDER BY n_synapses DESC;
```

## Missing skeleton generation

At the user's request, job `24153746` runs
`scripts/launch_postsynaptic_target_skeletons.py` to submit the 193,350 targets
missing from the completed availability inventory for **CAVE skeleton version 4**.
It rechecks availability in batches of up to 1,000 roots, skips service-refused
roots, and submits still-missing roots via `generate_bulk_skeletons_async`.
`skeleton_generation_v4/batches/` records each acknowledged submission for
resumption; `skeleton_generation_v4/summary.json` reports submission progress.
Acknowledgement means queued at CAVE, not successfully generated. The original
inventory's skeleton flags remain the earlier observation until refreshed with
new availability checks. This task does not download skeletons or run embeddings.
